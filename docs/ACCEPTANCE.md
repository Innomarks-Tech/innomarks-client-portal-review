# Acceptance checklist

All items begin unchecked. Tick only when evidence is recorded.

## Usability — 20%

- [ ] Visitors can identify a service and the next action.
- [ ] Discovery steps have helpful examples and an editable final review.
- [ ] Recoverable errors preserve answers and explain the next step.
- [ ] Staff can find a new lead and update its status without assistance.
- [ ] Real usability observations and resulting changes are recorded.

## Accessibility — 20%

- [ ] Complete core journeys with keyboard only.
- [ ] Screen-reader labels, errors, step transitions and success feedback verified.
- [ ] Contrast, focus, text enlargement and mobile reflow verified.
- [ ] Status meaning is independent of colour; reduced motion respected.
- [ ] Automated accessibility checks pass; limitations documented.

## Functionality — 20%

- [ ] Valid inquiries persist exactly once.
- [ ] Search, filtering, pagination, notes and status/history work.
- [ ] Staff authentication and access removal work.
- [ ] Notification failure preserves leads and can be retried safely.
- [ ] Relevant failure paths tested.

## Code quality — 20%

- [ ] Lint, type checking, production build and focused tests pass.
- [ ] Database migrations, generated types and access-policy tests committed.
- [ ] Secrets remain outside Git and client bundles.
- [ ] Dependencies and security advisors reviewed; serious findings resolved.
- [ ] Reusable UI components and readable implementation documented.

## Finishing — 20%

- [ ] Hosted core flow verified by Day 3 target.
- [ ] Final URL, HTTPS and optional supplied domain tested.
- [ ] Figma design and implementation are reconciled.
- [ ] README, setup, demo recording, evidence and handover complete.
- [ ] Submission release tagged; known limitations and external dependencies stated.

The 20% split is the owner's working scorecard, not verified organiser scoring. Do not award scores merely because items are implemented; verify the user outcome.
